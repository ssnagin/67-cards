# Формы входа и регистрации — 17 ноября 2026

## Контракт API

Реализация приведена к контракту PR #5, переданному владельцем:
https://github.com/ssnagin/67-cards/pull/5/files
Страница PR недоступна из среды, поэтому основанием служит описание владельца.
Spring-код PR в текущем checkout ещё отсутствует.

- `POST /api/auth/register`: `{ email, password }` → `{ id, email, role }`.
  Регистрация не возвращает токен. Поля имени в форме больше нет.
- `POST /api/auth/login`: `{ email, password }` →
  `{ accessToken, tokenType: "Bearer" }`.
- Защищённые запросы: `Authorization: Bearer <accessToken>`.
- Срок JWT — 15 минут, фактическая граница читается из `exp`.
- Нет refresh-токена, `/me`, серверного logout и cookie-аутентификации.

Гость перенаправляется с `/` на `/auth/login`. После регистрации выполняется
отдельный вход. После входа видны пустая страница, навбар и «Выйти».
Выход удаляет токен на клиенте и возвращает к форме входа. Это не отзывает
уже выданный JWT на сервере: он действителен до истечения срока.

## Состояние клиента

`useAuthSession` хранит токен в памяти и `sessionStorage` текущей вкладки:
перезагрузка сохраняет вход, закрытие вкладки завершает хранение токена.
Ключ разделён по режимам mock/real, чтобы мок-токен не попал в настоящий API.
При недоступности sessionStorage вход работает в памяти до перезагрузки.
Токен не помещается в cookies, URL или логи. sessionStorage доступен JavaScript;
это выбранный способ хранения до отдельного согласования другого решения.

`sub` и `role` читаются из JWT для UI, идентификатор пользователя не выдумывается.
Чтение claims не проверяет подпись и не является серверной проверкой личности.
Доступ к данным всегда проверяет API. Некорректный или истёкший токен удаляется.
Таймер, возврат во вкладку, переходы и API-запросы проверяют срок действия.
Ответ 401 защищённого маршрута завершает вход; 403 сохраняет токен и означает
недостаток прав. Автоматических повторов и refresh-запросов нет.

`useApi` использует `credentials: 'omit'`, не выполняет CSRF-запросов и
не отправляет Bearer на публичные auth-маршруты. Cookie-CSRF в Nuxt отключён,
поскольку текущая авторизация API использует только явный заголовок Bearer.
Исторические комментарии владельца сохранены, рядом добавлены уточнения
для текущего JWT-контракта.

## Временные моки

По умолчанию `NUXT_PUBLIC_API_MODE=mock`: два простых обработчика Nuxt повторяют
DTO регистрации и входа. Регистрация не хранит аккаунт, вход принимает любую
непустую почту и не проверяет пароль. Демонстрационный JWT без подписи имеет
claims sub, role, iss, iat, exp и срок 900 секунд. Он нужен только для UI и не
подходит для настоящего API. Базы, cookie-сессий и хеширования нет.

Для подключения PR установить `NUXT_PUBLIC_API_MODE=real` и
`NUXT_PUBLIC_API_BASE=http://localhost:16768` (адрес без `/api`). Моки в режиме
real отключены. Транспорт добавляет `/api/auth/...` из описания эндпоинтов.
Фактические CORS-заголовки, подпись и ответы Spring требуют проверки после
применения PR. Старые планы с refresh-токенами и cookie-логика не описывают
текущий контракт владельца.

## Оформление и проверки

Формы используют Tailwind и `BaseInput.vue` с `v-model` и стандартными атрибутами.
В main.css — директивы Tailwind и переменные цветов. После входа лишнего
контента нет. Комментарии владельца сохранены.

Сборка Nuxt прошла. ESLint без ошибок; в неизменённом profile.vue остаётся
прежнее предупреждение html-self-closing. Отдельно проверены sessionStorage,
Bearer-заголовок, credentials=omit, отсутствие CSRF/refresh, реакция на 401/403
и локальный выход. Внутренним диспетчером Nitro без открытия порта проверены
DTO моков, срок JWT и отсутствие Set-Cookie. Визуальная проверка и интеграция
с реальным Spring API не выполнялись; dev-сервер не запускался.
